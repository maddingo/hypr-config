# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal dotfiles for Hyprland + Noctalia (a Quickshell-based shell/panel for
Hyprland) + Alacritty, plus the shell scripts that install those tools and
symlink these configs into place on Ubuntu 24.04. There is no build/test/lint
step for the repo itself — "correctness" means the shell scripts behave
correctly and the config files are valid Lua/TOML for their respective tools.

## Layout

- `config-hypr/hyprland.lua` — main Hyprland config (Lua config format, not
  the legacy `hyprland.conf` syntax). Monitors, autostart, keybindings, window
  rules, animations. Ends with a `pcall`-guarded
  `require("noctalia").apply_theme()` — see the startup-race note below.
- `config-hypr/noctalia.lua` — colors auto-generated by Noctalia's theming
  system; applies the active color scheme to Hyprland border/group colors.
  Treat as generated output, not hand-authored config.
- `config-noctalia/` — Noctalia shell config (`noctalia-config.toml`,
  `colorschemes/`).
- `config-alacritty/` — Alacritty terminal config; `themes/noctalia.toml` is
  the Noctalia-generated color theme for Alacritty.
- `install.sh` — top-level entrypoint: links configs, installs Hyprland (via
  Ubuntu-Hyprland) if missing, builds Noctalia if missing.
- `link-config.sh` — symlinks `config-hypr` → `~/.config/hypr`,
  `config-noctalia` → `~/.config/noctalia`, `config-alacritty` →
  `~/.config/alacritty`. Existing non-symlink targets are backed up as
  `<name>.backup-<timestamp>`. Runs standalone or via `install.sh`.
- `hyprland-preset.sh` — non-interactive preset sourced by upstream
  Ubuntu-Hyprland's `install.sh --preset`, used to drive that installer
  without its interactive whiptail prompts. Only Y/N values are valid here.
- `install-noctalia.sh` — builds Noctalia from source on Ubuntu 24.04
  ("noble"), working around four gaps in the upstream README (old `just`,
  incomplete `libstb-dev`, GCC version requirement, missing `CC`/LTO
  mismatch). Copied into the Noctalia checkout and run from there.
- `noctalia-install.md`, `noctalia-ubuntu-bugreport.md` — reference notes on
  the Noctalia build process and a specific Ubuntu bug report.

## Common commands

```sh
./install.sh          # full install: link configs, install Hyprland/Noctalia if missing
./link-config.sh       # (re-)symlink configs only, no builds
./install-noctalia.sh --no-apt --mode debug   # rebuild Noctalia without re-running apt
```

## Key constraints (already enforced by the scripts, don't work around them)

- **Never link configs while Hyprland is running.** Hyprland rewrites a stock
  `~/.config/hypr/hyprland.lua` on startup, which clobbers or shadows the
  symlink. `link-config.sh` detects a live session (via
  `HYPRLAND_INSTANCE_SIGNATURE` or `pgrep Hyprland`) and refuses. Linking must
  happen from a TTY (`Ctrl+Alt+F3`) with Hyprland fully logged out on every VT.
- **`dots="N"` in `hyprland-preset.sh` is load-bearing.** Upstream
  Ubuntu-Hyprland's installer has no flag to skip installing its own KooL
  dotfiles, only an interactive prompt — this preset answers "N" so this
  repo's configs aren't overwritten by upstream's.
- **`install-noctalia.sh` must run from inside a Noctalia checkout** (it
  builds in place via `just`/meson), so `install.sh` copies it into
  `$NOCTALIA_SRC` before invoking it, rather than running it from this repo.
- `HYPRLAND_SRC` (default `~/Develop/Ubuntu-Hyprland`) and `NOCTALIA_SRC`
  (default `~/Develop/noctalia`) are cloned if absent and reused if present —
  don't assume a fresh clone on every run.
- **`config-hypr/noctalia.lua` is generated by Noctalia at runtime, not
  hand-authored, but `hyprland.lua` `require()`s it during Hyprland's own
  config parse.** On a machine where Noctalia has never run, that parse
  happens *before* Noctalia's `hyprland.start` autostart entry has had a
  chance to launch it and write the file, so the very first parse hits a
  missing module ("module noctalia not found") — a one-time startup race, not
  a real bug. `require("noctalia")` in `hyprland.lua` is wrapped in `pcall`
  for this reason; don't remove the guard. The generated file is also
  committed to the repo so a fresh clone/link already has it and normally
  won't hit the race at all.
